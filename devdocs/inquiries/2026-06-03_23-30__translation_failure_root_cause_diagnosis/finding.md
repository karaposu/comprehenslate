# Finding: translation_failure_root_cause_diagnosis

## Question

From `_branch.md`. The translation in `mytrasnlations/5th_word/eng.md` (an English rendering of Said Nursi's Fifth Word from the Risale-i Nur, translated from Ottoman Turkish) exhibited two distinct failure types that the user flagged across three rounds of review: register pull-up across ≥8 lexical items (corvée, cauldron, morsel, parable, scrubs-the-mess-tin, Padishah, wave-tossed, wayward — all cases of unmarked plain-Turkish source words being rendered into marked/archaic English) and a polysemy mis-resolution on the word *nefer* (rendered as "foot-soldier" when the construction required the general sense "an individual / one of them"). The framework documents intended to govern this translation — `advanced_principles.md`, `notes.md`, and `harmony_layer.md` (collectively, the comprehenslate framework) — were loaded and consulted before the translation, yet the failures still occurred.

The user asked: what is the actual root cause? Three competing hypotheses were offered:
- **H1** — the fault lies in the framework documents themselves (something is missing or wrong in them).
- **H2** — the fault is an AI translation issue, specifically "bulk translation all pages" behavior. The user qualifies this immediately ("there are not so much text, not like 20 pages") — signaling skepticism toward this hypothesis themselves.
- **H3** — the fault is the absence of an explicit failure-modes catalog in the framework. The user attaches a sub-question to this hypothesis: aren't the existing principles and translation logic already implicit failure modes? In other words, why would we need an explicit catalog if the positive principles already imply what to avoid?

The goal stated in `_branch.md`: the user wants a diagnosis precise enough to act on — knowing the *layer* where the fix belongs (documents / process / catalog / framing), the *specific change* required at that layer, and the *causal chain* that produced the failure so future symptoms can be traced. The user is treating this failure as a system-improvement diagnostic, not as a one-off bug; the explicit "what would fail" criterion in the goal rules out vague generalities ("be more careful"), blame-deflection ("AI models do that"), and fixes that target the wrong layer.

## Finding Summary

- **The cause is multi-layer, not single.** The translation failed because four causal layers stacked on top of one another, not because of a single mistake. Each layer alone would have been catchable; together they produced an undetected failure pattern across multiple words. The user's three hypotheses correctly name two of the four layers but miss the proximate trigger and the architectural pattern.

- **The proximate trigger was the AI's interpretation of "C1 English speakers" as license for elevated vocabulary.** "C1" in the CEFR (Common European Framework of Reference for Languages) marks reader capability, not target-text vocabulary altitude. The AI mis-mapped a comprehension-capability marker into a vocabulary-level license, and that misread launched the entire register pull-up cascade. The framework had no rule for interpreting audience-specification descriptors, so the misread proceeded unchallenged.

- **The structural amplifier was `harmony_layer.md`'s tier system actively classifying register as Tier 3 (sacrificeable, "doesn't change meaning").** This is not just an absence of guidance — it is an active misclassification. The doc states its own ranking principle as "the closer a harmony component is to carrying meaning, the higher its priority." When source text uses register-alternation as a structural device (the parable's plain folk-register grounding the decoded section's high theology), register IS meaning-carrying. By the doc's OWN principle, register-as-alternation should be Tier 1. The doc therefore contradicts itself on this case — an internal-inconsistency finding, verifiable from the doc alone.

- **The meta-layer cause is that the framework is a positive-principle list with no explicit failure-mode catalog.** Principles and failure modes are not interchangeable cognitive instruments. Principles are *prescriptive* (read while doing the task — guides attention to what to achieve); failure modes are *diagnostic* (read as a separate check — guides attention to recurring error patterns). When a task is in progress, attention runs in prescriptive mode; pattern-recognition for failures requires a different attention mode that an explicit catalog enables. The user's sub-question — "don't principles count as failure modes?" — gets a definite NO. Two reasons combine: cognitive roles differ; AND failure modes name multi-principle interactions that no single principle predicts. Register pull-up is the product of several individually-defensible choices ("use sophisticated vocabulary" + "preserve source meaning" + "the audience is C1") interacting in a misread way; no single positive principle in the framework predicts that combination as a failure.

- **The architectural pattern is that AI-extracted lessons live in session memory, not in the framework documents.** Two feedback memory files (`feedback_translation_register.md` and `feedback_translation_polysemy.md`) were created post-failure to capture the lessons. These live at `/Users/ns/.claude/projects/.../memory/` — a separate location from the comprehenslate framework documents at `/Users/ns/Desktop/projects/comprehenslate/`. There is no ingestion path from memory to docs. The next session loading the framework still sees the failure-permitting documents. The framework cannot learn from its own breakdowns.

- **The user's hypotheses, scored against this diagnosis:** H1 (fault in docs) **CONFIRMED** — specific gaps plus the active mis-classification of register. H2 (AI bulk translation) **MOSTLY FALSE** — the text is short (~70 lines, ~9 paragraphs); a related true finding (no per-section audit step in the framework's process model) is re-located under H1 as a process-shaped gap. H3 (lack of failure modes) **CONFIRMED** — but more sharply than the user framed it: principles do NOT substitute for failure modes; the framework needs both as separate complementary instruments. Two additional causes not in the user's hypotheses are added: the C1-misread as proximate trigger, and the lesson-siloing as architectural cause of recurrence.

- **The fix is sequencable across two effort levels, both viable.** *Minimum Viable Fix* (~2-4 hours): the audience-spec / skopos rule (catches future C1-misreads); the polysemy-disambiguation principle (catches future *nefer*-class polysemy failures); the documented-failure-trace practice (turns the failed `eng.md` into a calibration entry rather than a hidden bug); the surgical register tier fix in `harmony_layer.md` (resolves the internal inconsistency). *Emergent Assembly* (~1-2 days, recommended): the four MVF pieces plus a restructured multi-axis harmony report (the framework's self-audit instrument gains register and markedness sections) plus a failure-modes catalog seeded by Antoine Berman's twelve "deforming tendencies" (a 1985 translation-studies catalog that already names "ennoblement" — register pull-up — by a different name), filtered to entries that have actually fired or are likely to fire in this user's corpus, plus AI-specific entries the user's failures revealed.

- **Two larger items are intentionally deferred, not killed.** A memory-to-spec ingestion architecture (a flow where AI-extracted lessons feed back into framework edits over time) is *deferred with revival trigger*: when ≥3 additional translation failures have been diagnosed through separate inquiries like this one, the marginal cost of one more inquiry exceeds the architectural cost, and the deferred item should be promoted to active. A wholesale tier-system replacement (replacing the 4-tier ranking with failure-mode-severity prioritization) is parked as a *research frontier*: structurally cleaner long-term but requires migration work and severity-calibration specification that exceeds the current scope.

## Finding

To explain how the diagnosis lands, it helps to set the scene first. Comprehenslate is a translation methodology the user is building, encoded in three files at the project root: `advanced_principles.md` (worked examples of how the methodology behaves on specific principles), `notes.md` (an inventory of around sixty principles extracted from classical Islamic textual-analysis traditions, each framed as "comprehenslate should detect / preserve / flag..."), and `harmony_layer.md` (the operating architecture — a three-pass translation procedure plus a four-tier priority system for resolving conflicts between competing preservation goals). The Fifth Word translation in `mytrasnlations/5th_word/` is an English rendering of a short Ottoman Turkish text by Said Nursi (an early-20th-century Islamic theologian); the parable narrates a wartime barracks story in plain folk diction and then decodes it into elevated Arabic-Persian-Turkish theological vocabulary. The deliberate register alternation — plain folk grounds high theology — is the parable's central rhetorical device. The translation flattened that alternation by pulling the folk register upward into ornate English, and that failure was missed by the framework's self-audit instrument (the harmony report at the bottom of `eng.md`) even though the audit was written using the framework's own categories.

This is the failure the user came to diagnose. The diagnosis proceeds in four sections: the four-layer causal stack (Section 1); how the user's hypotheses map to the stack (Section 2); the recommended fix-program at two effort tiers (Section 3); and the items deferred to future work (Section 4).

### 1. The four-layer causal stack

The failure had four layers of cause, each at a different leverage point. Naming all four matters because intervening at one layer alone leaves the other layers active.

**Layer 1 — Proximate (the trigger event).** The AI's audience-specification interpretation step misread "C1 English speakers" as a license for elevated vocabulary. The CEFR scale that "C1" refers to is a reader-capability scale: A1/A2 (beginner), B1/B2 (intermediate), C1/C2 (proficient/mastery). "C1" indicates the reader CAN handle complex syntax and unusual vocabulary; it does NOT say the target text SHOULD use those features regardless of source register. The AI collapsed capability into license. Evidence: the AI's own first-message statement in the conversation — "I'll use sophisticated literary register" — captured this misread as a stated interpretation. Without this misread, the register pull-up cascade would not have fired with the same force. A parallel proximate trigger applies to the polysemy failure: the parable's military framing (soldiers, battalion, drill, padişah) primed metaphor-momentum to override the local genitive construction in "*serçe kuşunun bir neferi*" (one *nefer* of the sparrow). The AI picked the military sense of *nefer* (foot-soldier) because the surrounding context was military, even though the genitive construction (sparrows do not have armies) forced the general sense (an individual member).

**Layer 2 — Structural (the amplifier in the documents).** Two structural defects in the framework allowed the proximate trigger to produce undetected failures. The first defect is an active misclassification: `harmony_layer.md` classifies "register consistency" as Tier 3 ("important for reader comfort but doesn't change meaning"). The doc's own ranking principle states that the closer a harmony component is to carrying meaning, the higher its priority. When source text uses register-alternation as a structural device — when plain folk diction grounds elevated theology, as the Fifth Word does — register IS meaning-carrying. By the doc's own principle, register-as-alternation should be Tier 1. The doc fails to distinguish register-as-style (which is Tier 3 correctly) from register-as-alternation (which should be Tier 1). The misclassification is an in-doc proof of internal inconsistency, not just an absence of guidance. The second defect: the harmony report at the bottom of the translation file (the framework's self-audit instrument) has zero register-related entries. Its content is generated from the tier system, so when the tier system silently demotes a feature, the audit silently omits it. The audit is structurally blind to the failure mode that occurred — the framework cannot see what its own classification told it not to look for.

**Layer 3 — Meta (the design choice in the framework).** The framework is a positive-principle list, not a diagnostic catalog. Across all three documents — `advanced_principles.md`'s worked examples, `notes.md`'s sixty-or-so principles, `harmony_layer.md`'s tier system — there is no explicit failure-mode artifact. Every entry states what GOOD output looks like. None state what TYPICAL BAD output looks like as a named pattern. This is a design choice with operational consequence: principles and failure modes engage different cognitive operations. Principles are prescriptive — they guide attention while DOING the task ("what should I achieve here?"). Failure modes are diagnostic — they guide attention to recurring error patterns, typically read as a separate check ("did I commit any of N known errors?"). A translator following only principles is in prescriptive mode throughout, with no opportunity for the pattern-recognition mode an explicit catalog enables. This is the structural answer to the user's sub-question.

The user asked: aren't the existing principles already implicit failure modes? The answer is NO, for two reasons that combine. First, cognitive roles differ. The principle "preserve word order" implies, in some abstract sense, "don't break word order" — but the implication requires the operator to do extra mental work that prescriptive-mode attention does not provide. Second, and more importantly, failure modes name MULTI-PRINCIPLE INTERACTIONS that no single positive principle predicts. Register pull-up is the product of three individually-defensible choices interacting in a misread way: "use sophisticated vocabulary" (a vague positive value the AI inferred from "C1"); "preserve source meaning" (a real framework principle); and "the audience is C1" (an audience spec from the user). No single positive principle in the framework predicts this combinatorial failure. Only an explicitly named failure mode — "register pull-up: AI tendency to render plain folk-vocabulary with marked-English equivalents (corvée, cauldron, morsel, etc.); recognition signature: source word is unmarked everyday vocabulary, target word is marked literary / archaic / period-specific" — can surface it as a recognizable pattern. The user's intuition that principles "should" count was partly right (they imply consequences) but practically insufficient (they don't substitute).

**Layer 4 — Architectural (the learning gap).** The framework has no path for absorbing failures into its own documents. After the user flagged the failures, the AI extracted two feedback-memory files capturing the lessons: `feedback_translation_register.md` and `feedback_translation_polysemy.md`. These were saved at `/Users/ns/.claude/projects/-Users-ns-Desktop-projects-comprehenslate/memory/` — a separate location from the comprehenslate framework documents. There is no documented ingestion mechanism that propagates these lessons back into `harmony_layer.md`, `notes.md`, or `advanced_principles.md`. The architectural consequence: next session, with the same framework loaded, the same failures can recur because the docs still permit them. The lessons exist only in the AI's per-session memory layer, which is volatile across sessions and invisible to the user. The framework cannot learn from its own breakdowns; only the AI session memory learns, and only for the next session of the same agent on the same machine.

### 2. How the user's hypotheses map to the four-layer stack

The user offered three hypotheses joined by "or." Mapping each to the four-layer stack clarifies which layer they were targeting and what they missed.

**H1 — fault in `advanced_principles.md`, `notes.md`, `harmony_layer.md`.** CONFIRMED. This is the Structural layer (Layer 2). The docs do have specific gaps: no register-matching principle, no markedness-matching principle, no polysemy-disambiguation principle, no failure-mode catalog. Plus the active misclassification (register at Tier 3 contradicting the doc's own ranking principle). The user's hypothesis correctly targets this layer.

**H2 — AI bulk translation issue.** MOSTLY FALSE. The user named this hypothesis as "bulk translation all pages" and immediately added "there are not so much text, not like 20 pages." The size evidence directly disconfirms volume-based bulk-translation framings: the text is ~70 lines, ~9 paragraphs. However, a related true finding exists nearby and is re-located under H1: the framework's three-pass process model does not specify a per-section register audit step between translation passes. The AI translated in one continuous pass without a sectional checkpoint. This is a process-step gap, not a volume issue. Re-locating it to H1 keeps the diagnosis precise.

**H3 — lack of explicit failure modes.** CONFIRMED. This is the Meta layer (Layer 3). The framework's choice to be a positive-principle list rather than including a failure-mode catalog is a real design choice with real operational consequences. The user's attached sub-question — "don't principles count as failure modes?" — gets a definite NO. The cognitive-role argument and the multi-principle-interaction argument (Section 1) both refute the substitution claim. Failure modes are a complementary instrument the framework is missing entirely.

**H4 added — audience-spec interpretation as proximate trigger.** This is Layer 1 and was not in the user's three hypotheses. The framework has no rule for interpreting audience-level descriptors ("C1 English speakers," "for academics," "for children"). The C1 misread proceeded because the framework didn't constrain interpretation. The fix is a specific rule (see Section 3, MVF item 1).

**H5 added — lesson siloing as architectural cause.** This is Layer 4 and was not in the user's three hypotheses. Lessons saved to AI session memory do not flow back to the framework docs. The pattern ensures recurrence on future unknown failures even after this round of fixes addresses the known patterns. The fix is either a lightweight in-narrative substitute (the documented-failure-trace practice; see Section 3) or a heavier architectural addition (deferred; see Section 4).

### 3. The recommended fix-program — two effort tiers

The fix is a coordinated set of interventions across the four causal layers. Two tiers are offered, both viable; the user picks the depth of intervention they want now.

#### 3a — Minimum Viable Fix (MVF, ~2-4 hours)

Four pieces, all individually viable, that touch the proximate trigger, the structural amplifier, and the architectural learning gap (in narrative form).

**MVF-1: Audience-spec / skopos interpretation rule.** Add a rule to `notes.md` (or a new file referenced from `harmony_layer.md`) specifying how the translator should interpret audience-level descriptors. The rule has a default: when the user passes a CEFR descriptor like "C1 English speakers," the AI defaults to a "skopos" (translation purpose) of "match source register faithfully; preserve register-alternation as Tier 1 structural feature; do NOT interpret audience-capability descriptors as vocabulary-altitude licenses." The user can override per translation. The rule directly prevents the C1-misread (the proximate trigger). Effort: small (one rule + worked example showing the C1 case before and after). Layer addressed: Proximate.

**MVF-2: Polysemy disambiguation principle.** Add a principle to `notes.md`: when a source word has multiple senses (polysemy), the local construction (genitive, agreement, plausibility) picks the sense, not the surrounding metaphor's momentum. The principle includes the plausibility test: can the referent actually do what the metaphor-sense requires? (In the *nefer* case: sparrows have no army, so "soldier of the sparrow" fails the test; "an individual of the sparrow species" passes.) Effort: small (one principle + the *nefer* worked example). Layer addressed: Proximate (for polysemy failures).

**MVF-3: Documented-failure-trace practice.** Add a short header to the existing `mytrasnlations/5th_word/eng.md` explicitly marking it as a documented failure trace — not as a clean translation. Cross-reference this finding. The file becomes the framework's first calibration entry: a recorded instance of failure that future translators (human or AI) can read to understand the recurring patterns. Effort: trivial (a few lines added to the top of the file). Layer addressed: Architectural (in narrative form, as a lightweight substitute for the full memory-to-spec ingestion architecture deferred to future work).

**MVF-4: Register tier surgical fix in `harmony_layer.md`.** Edit `harmony_layer.md`'s tier list to either (a) split "register consistency" into two sub-categories — "register-as-style" at Tier 3, "register-as-alternation" at Tier 1, with a gating sentence stating when each applies — or (b) upgrade "register" to Tier 1 with a gating condition that explicitly names register-as-alternation as the meaning-carrying case. Either choice resolves the internal inconsistency the doc has against its own ranking principle. Effort: small (a few lines edited in one section). Layer addressed: Structural.

Together, MVF-1 through MVF-4 address three of four causal layers (Proximate, Structural, Architectural-via-narrative) and prevent the documented register-pull-up and polysemy failures from recurring with the same triggers. The Meta layer (no failure-mode catalog) is touched lightly via the principles added in MVF-1 and MVF-2 but is not fully addressed at this tier — that gap is filled at tier 3b.

#### 3b — Emergent Assembly (recommended; ~1-2 days total)

All four MVF pieces plus three additional pieces that close the Meta layer and harden the Structural layer.

**EA-5: Multi-axis harmony report restructure.** Reorganize the existing harmony report at the bottom of each translation file. Currently the report contains sections like "Tier 1 preserved" and "Tier 4 sacrificed." Add four required sections: (a) Register Fidelity Audit (per-section source/target register comparison; flags register pull-up), (b) Markedness Audit (per-word source/target markedness check; flags marked-target-for-unmarked-source cases), (c) Per-Section Comparison (which sections of the source map to which sections of the target, register-by-register), (d) Failure-Mode Scan (each entry from the failure-modes catalog checked against the translation; "not observed" is an acceptable result, but the entry must appear in the scan). Effort: medium (restructure the report template; specify the four section schemas). Layer addressed: Structural. Couples with MVF-4 (the tier fix) and EA-7 (the catalog the failure-mode scan references).

**EA-6: Failure-modes catalog (seeded by filtered Berman + AI-specific entries).** Author a new failure-modes section, either as a new file or as a section in `harmony_layer.md`. Seed it from Antoine Berman's "twelve deforming tendencies" (a 1985 catalog from translation studies — Berman, "La traduction et la lettre, ou l'auberge du lointain"). His entries include "ennoblement" (which is exactly the register pull-up pattern, named in classical translation studies forty years ago), "exoticization," "rationalization," "clarification," "qualitative impoverishment," and seven others. Filter Berman's twelve to the entries that have actually fired in this user's corpus or are structurally likely to fire (cultural-domain check: Berman wrote about classical European literary translation; some entries will not apply to Risale-i Nur translation). Add AI-specific entries that Berman doesn't cover: metaphor-momentum override (the polysemy failure), audience-spec misinterpretation (the C1 misread), transliteration over-application (the tendency to keep too many source-language terms italicized rather than translating them). Each entry has a fixed structure: name, recognition signature, structural mechanism (why this fails), corrective, related principles, concrete examples. Effort: medium-to-large (largest single piece in the Emergent Assembly). Layer addressed: Meta. The user's sub-question about whether principles already count as failure modes is settled by adding this catalog as a separate complementary instrument.

**EA-7: Diagnosis communication and inquiry-link.** Add a brief section to one of the existing framework documents (or a new `README.md` at the project root) cross-referencing this finding as the inaugural calibration entry. The framework now has a documented history of one diagnosed failure pattern and the fixes applied. Effort: trivial. Layer addressed: Architectural-via-narrative; complements MVF-3.

The Emergent Assembly closes all four causal layers without requiring the heavy memory-to-spec ingestion architecture deferred to Section 4. The framework becomes a "diagnostic-first framework with documented calibration" — translations produce harmony reports that include failure-mode scans; failure-mode-positive translations get documented as calibration entries; calibration entries accumulate into evidence for future catalog additions. The loop is human-authored rather than automated, but it functions as a feedback loop.

## Reasoning

The diagnosis arrived through five disciplined passes: surfacing the territory's items with relevance tags; sensemaking to build a stabilized causal model; decomposition to convert the action program into tractable pieces; innovation to generate candidate approaches; critique to adversarially evaluate them. The reasoning below explains why this answer holds over the alternatives that were considered and tested.

### Why the four-layer causal model survived

Sensemaking's Phase 3 (Ambiguity Collapse) tested six competing interpretations of the cause structure. Five resolved at HIGH confidence with structural arguments; one at MEDIUM confidence. The most consequential collapse was Ambiguity 1: is the C1-misread the primary cause, or is the framework's tier-3 register classification the primary cause? Both turned out to be real, at different layers. The C1-misread is a TRIGGER; the framework's tier system is an AMPLIFIER that lets the trigger produce undetected outputs. The single-cause framings — "just the AI made one wrong call" or "just the docs are missing things" — were both eliminated because each ignores the other's evidence. The framework gap is documented in four surfacing items (the tier classification in `harmony_layer.md`; the absence of register-related entries in the harmony report at `eng.md`'s bottom; the absence of any register-matching principle in `notes.md`; the absence of any failure-mode catalog across all three docs). The trigger is documented in the conversational record (the AI's explicit "I'll use sophisticated literary register" statement and subsequent self-diagnosis as "register pull-up"). Both layers are real; both need fixes.

Ambiguity 2 settled the user's sub-question definitively. The counter-interpretation that principles already imply failure modes ("preserve word order" implies "don't break word order") was tested on structural grounds. It failed for two reasons. First, cognitive roles differ: prescriptive mode (read while doing) and diagnostic mode (read as a separate check) are different attention modes that the same operator cannot occupy simultaneously while task-focused. Second, failure modes name multi-principle interactions that no single principle predicts: register pull-up emerges from the interaction of three individually-defensible choices, none of which predicts the combinatorial failure. The empirical disconfirmation also held: the framework HAS positive principles that, if followed, would have prevented the failure (the small-cycle-example principle in `advanced_principles.md` explicitly says examples should be culturally adapted to the target audience, which a careful translator would have applied to avoid exoticizing the parable). Yet the failure happened. Principles did not function as failure modes in this case.

Ambiguity 3 closed H2. Volume evidence — the text is short (~70 lines) — directly disconfirms "bulk translation" as a primary cause. The related true finding (no per-section audit step in the framework's process model) was re-located under H1 as a process-shaped gap, not abandoned.

Ambiguity 4 produced the watershed finding via the Definitional / Internal-Consistency perspective: `harmony_layer.md` contradicts its own ranking principle on the register-as-alternation case. This is an in-doc proof — the structural argument doesn't require external evidence. The internal inconsistency is the structural argument; the empirical failure corroborates.

Ambiguity 5 settled the architectural question. Doc fixes alone, even if comprehensive for known patterns, do not address future unknown failure types because the framework cannot ingest new lessons. The architectural argument is sound; the engineering cost is real; the resolution sequences the two (doc fixes first; architectural addition deferred with revival trigger).

Ambiguity 6 (the specific-vs-pattern check) confirmed that the 8 register words and the *nefer* polysemy are SPECIFIC EXAMPLES of a wider pattern, not the whole problem. Three-dimensional consistency (consistent direction, consistent location, consistent type) plus external corroboration (Berman's "ennoblement" from translation studies) plus the AI's own admission of suspected-but-uncaught instances ("brand you a mutineer, inflict the punishment, tilth, August and All-Generous, Lordly wisdom, beast of prey, trench-post") all converge on pattern-level diagnosis.

### Why the Emergent Assembly survived over individual fixes

Innovation produced nine surviving candidates. Critique tested them against eight evaluation dimensions (six default plus two project-specific risk dimensions: recurrence prevention and trigger coverage). The Emergent Assembly survives because it dominates the individual-survivor space on the critical dimensions: it addresses all four causal layers (where any individual candidate addresses one or two), it preserves the per-piece feasibility of the individual survivors (the assembly's pieces are each independently viable), and it composes without requiring the heavy memory-to-spec architecture (the documented-failure-trace practice substitutes in narrative form for the architectural layer). The Minimum Viable Fix sub-assembly was surfaced by critique as a user-choice variant: when the user wants minimum cost / maximum immediate effect, MVF is the right disposition; when they want the full diagnostic-first framework, the Emergent Assembly is.

### Why some candidates were refined, deferred, or parked

S2 (Berman's twelve as catalog seed) was REFINED, not adopted wholesale, because Berman's catalog was authored for classical European literary translation; some entries may not apply to Said Nursi's Risale-i Nur translation, and some AI-specific failures (metaphor-momentum override; transliteration over-application) don't match any of Berman's twelve. The refinement: use Berman as a CHECKLIST during catalog authoring; include only the entries that have fired or are likely to; add AI-specific entries that Berman doesn't cover.

S1 (rules-with-violations restructure) was REFINED to scope-restricted application because the wholesale rewrite of all existing principles is high-overhead and risky in the short term, even though it's structurally clean long-term. The catalog from EA-6 uses the rules-with-violations format for new entries; the wholesale conversion of existing principles is parked as a research frontier.

S6 (memory-to-spec ingestion architecture) was DEFERRED because the engineering cost is real and the marginal value at current translation volume is uncertain. The documented-failure-trace practice (MVF-3) is a narrative-form substitute that handles the same layer at much lower cost. The revival trigger is explicit: ≥3 additional failure-diagnosis inquiries, at which point per-inquiry cost exceeds the architectural investment.

S7 (tier-system replacement) was parked as RESEARCH FRONTIER because the migration cost is high and the severity-calibration scheme requires data the framework doesn't yet have. The principal MVF-4 (surgical tier fix) achieves the same immediate effect via repair rather than replacement.

No candidate received a KILL verdict. Every candidate either survived clean, refined to a viable form, deferred with revival trigger, or was parked as a research frontier with structurally clean reasoning. The fitness landscape is densely populated in the viable region; the dead region is empty.

### What this finding does NOT claim

The finding does NOT claim that fixing the framework alone will catch all future failures. The diagnosis explicitly identifies the AI's behavior layer (the proximate trigger) as in-scope-via-trigger, not as a directly modifiable target — the framework can bias the AI's behavior by naming failure modes explicitly and by specifying interpretation rules, but the AI's training and prompt-handling are not framework-level levers. The MVF and Emergent Assembly target the layers the user CAN modify. This is a deliberate scoping decision made during sensemaking's Frame-exit Completeness perspective; it was tested and held.

The finding does NOT claim the diagnosis is exhaustive. Two unexplored regions were flagged but not addressed: user-translator collaboration patterns (e.g., a rule requiring the AI to ask clarifying questions about audience before translating) and source-text-pre-analysis (a rule requiring the AI to characterize source register before translating). Both are adjacent to S9 (the audience-spec rule) and could complement it in future iterations. They are not gaps in the current diagnosis; they are seeds for future work if S9 proves insufficient.

The finding does NOT claim Berman's catalog is the final word on translation failure modes. Berman's twelve are a SEED — a well-grounded starting point from translation studies. The catalog needs to evolve with the user's specific corpus (Islamic theological texts, Ottoman Turkish, Arabic-Persian-Turkish compound vocabulary).
