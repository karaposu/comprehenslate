### Mechanism 1: Combination (Generator)
- **Generic:** Combine Dreyfus 5-stage expertise (surfacing R1) + 5 stratification dimensions (R8) + 9 handling actions (R9) → 4-component template with expertise-depth-tier ladder + 2-category action vocabulary + 1 bridge.
- **Focused:** Combine Said Nursi corpus specifics (kalam / fiqh / tafsīr / Bediuzzaman) + biblical scholarship anchors (Documentary Hypothesis JEDP / Nestle-Aland critical apparatus) + Polanyi tacit knowledge → cross-cultural specialist-tacit demonstration at expert level.
- **Contrarian:** Combine A1 cultural-reference-recognition's DOMESTICATE-disfavored policy + A2's specialist vocabulary → would A2 have a "specialist-shorthand-disfavored" policy? Tested: A2 does NOT have a foreignization-vs-domestication tension because specialist terminology is the desired register (the expert wants to READ specialist terms, not see them paraphrased). USE-TECHNICAL-VOCABULARY-FREELY at expert is correct; no project-policy override needed. Sets the boundary between A2 (no policy override) and cultural-reference-recognition (DOMESTICATE-disfavored) cleanly.

### Mechanism 2: Absence Recognition (Generator)
- **Patch-level (gap):** A "specialist-vs-canonical-source-text" distinction is partially missing — a specialist may know SECONDARY literature but not PRIMARY canonical texts (or vice versa). Address in P2's primary-source-canon dimension within expertise-depth-tier.
- **Patch-level (gap):** Specialist-debates-recognition handling — already covered by INVOKE-SPECIALIST-DEBATES + ATTRIBUTE-VIEW-TO-SCHOOL actions. No new gap.
- **Redesign-level (missing):** What would exist if designed from scratch? An `audience.expertise_set: list[(domain, level)]` field at audience-level for multi-domain readers (a reader who is `expert` in Islamic theology AND `lay` in physics). Currently handled by single-domain default; multi-domain is a future inquiry.
- **Redesign-level (already-present-in-different-form):** The project ALREADY informally distinguishes domain expertise — Said Nursi translations are typically glossed at the lay level by adding parenthetical Islamic-tradition context. The framework formalizes what's already informal practice.

### Mechanism 3: Domain Transfer (Generator)
- **Generic (cross-domain):** Medical translation studies — patient-information leaflets vs medical-journal articles stratify reader expertise on a 5-tier (patient / informed-layperson / general practitioner / specialist clinician / research scientist). Maps to A2's lay → expert progression with cross-domain validity.
- **Native-domain (translation studies):** Newmark / Venuti / Aixelá taxonomy on culture-specific items + Gotti on specialized discourse — already established the per-expertise-level handling tradition.
- **Contrarian (cross-domain):** Wine sommelier certification — beginner / informed / certified / advanced / master — 5-tier expertise stratification with operational handling differences at each level (how the sommelier communicates with patrons differs by patron's expertise). Parallel framework illustrates A2's structure.

### Mechanism 4: Extrapolation (Generator)
- **Generic:** If translator-AIs improve at runtime domain-detection, the configuration burden on the user may decrease — the AI could auto-detect source domain AND adapt expertise level by observing reader feedback.
- **Focused:** If the project expands to multiple specialist-domain corpora (Bible scholarship corpus + Islamic theology corpus + philosophy corpus), the framework already supports each via single-domain-per-config (each translation job's source-domain implicit).
- **Contrarian:** If AI capability matures to where translator-AI can DYNAMICALLY estimate reader's expertise from feedback (clarifying questions, hover-clicks, etc.), the static A2 configuration may become obsolete — replaced by adaptive runtime estimation. Long-horizon (5-10 years). Research frontier; preserved as observation.

### Mechanism 5: Lens Shifting (Framer)
- **Generic:** Under what conditions does "expert" level become wrong? When the reader is a specialist BUT in a DIFFERENT sub-specialty within the same domain (an Ash'ari-school specialist reading a Mu'tazila-focused text knows kalam vocabulary but not Mu'tazila-specific internal debates). Sub-specialty distinction is handled by conservative-bias-LOWER + per-translation-job conscious config.
- **Focused:** For Said Nursi → English target reader (most likely Western secular), conditions are: A2=lay as default; possibly A2=aware for general "world religions" readers; rarely A2=expert (only Nursi scholars). The configuration default should be conservative LOWER.
- **Contrarian:** Under conditions where the SOURCE TEXT itself uses simplified register (Nursi sometimes addresses lay audience, sometimes scholar audience), the source's intended audience may differ from the configured target audience. RESOLUTION: configuration takes precedence (the AI follows the configured A2 level, not the source's intended audience). This is a project policy.

### Mechanism 6: Constraint Manipulation (Framer)
- **ADD-direction:** Add constraint "every level must include at least one non-Western canon example" — forces cross-cultural illustration; prevents Western-canon lock-in (mirrors A1 cultural-reference-recognition's CC-B refinement).
- **ADD-direction:** Add constraint "Said Nursi corpus example position must be explicit at each level" — anchors the project's primary use case at every level definition.
- **REMOVE-direction:** Remove constraint "5 levels per user directive" — what if A2 needs 3 or 4 levels? **Flag: REMOVE-direction explored; no candidate produced — the constraint is non-removable per explicit user directive that A2 should be 5 levels.**

### Mechanism 7: Inversion (Framer)
- **Component-level:** "A2 measures DEPTH of expertise" → inverted: "A2 measures BREADTH of expertise (number of domains known)" → wrong direction; breadth is captured by domain-scope, settled as single-domain.
- **System-level (depth-axis):** "A2 captures domain-specialist knowledge" → inverted: "A2 captures domain-non-specialist (general) knowledge" → that's A1; conflation rejected.
- **System-level (existence-axis):** "A2 captures reader's expertise in source's domain" → existence: "Could A2 be ZERO levels and just be a binary 'specialist or not'?" → degenerate; gradient matters per Dreyfus 5-stage anchor.
- **System-level (identity-axis):** "Domain expertise = depth of KNOWLEDGE" → identity: "Domain expertise = familiarity with the COGNITIVE STYLE of the domain (specialist way of thinking)" — interesting reframe but the 5 stratification dimensions already capture this (conceptual schema; discourse conventions). Doesn't change spec materially.
