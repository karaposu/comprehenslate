## (c) Candidate Verdicts (prosecution · defense · collision)

### CAND-1 — Diagnosis-core + locus verdict (un-invoked 3-Pass; instinct-right/locus-refined) → **SURVIVE + REFINE**
- **Prosecution (external-anchor, P1):** "orphaned / never invoked" overstates. Rule 1 forces reading `harmony_layer.md` in full, so the 3-Pass is in the model's context every run. It wasn't *absent*; it just wasn't *executed as steps*. "Orphaned prose the workflow never calls" blurs read-but-unused with never-present.
- **Defense:** the load-bearing claim is not "unseen" but "un-proceduralized" — Step 5 (line 73/78) applies the file's *Tier policy*, never its *method*. That survives the quoted text exactly.
- **Collision → REFINE:** sharpen the wording from **"orphaned / never invoked"** to **"in-context but un-proceduralized"**: the 3-Pass is read (Rule 1) but nothing in Step 5 makes the model *execute* it as ordered gates. This is not cosmetic — it changes the fix's target: the fix is not "make the model aware of the 3-Pass" (it already is) but "force its *execution*." Directly dovetails with the prior finding's "ran in spirit as one motion."

### CAND-2 — Relationship: REFINES+COMPLEMENTS, one cause → two gates (P3) → **SURVIVE + REFINE (the sharpest finding)**
- **Prosecution (the demotion / lets-prior-off-easy argument, user 2a):** if the root cause is "the 3-Pass is never proceduralized," then the prior's "fluency-first pass, no post-draft checkpoint" is a **downstream symptom** of that cause, not a co-equal sibling finding. "REFINES + one shared cause → two gates" frames prior and current as *level peers*; a cause and its symptom are not peers. Calling it "co-equal / two faces of one cause" understates that this inquiry found the **cause** of which the prior found an **effect** — and that flattening protects the prior finding (and the AI that authored it).
- **Defense:** "supersede" is wrong on two counts grounded in evidence: (i) the prior's *remedy* — the post-draft check — **survives** as Pass-3's gate (a superseded finding's fix does not survive); (ii) the prior's *description* (fluency-first single motion) is **not false** — it is accurate at its level; this inquiry adds the WHY. "Refines" = same direction, deeper/more precise. That is exactly this relationship.
- **Collision → REFINE:** keep **REFINES** (not supersedes — the fix survives, the description isn't false) **but carry an explicit demotion note**: the prior's "no post-draft checkpoint" is demoted from **root-cause** to **one of two proximate gates**, both downstream of the single root cause (un-proceduralized 3-Pass). Replace the flat "co-equal / two faces" with the precise structure: **two temporally-distinct gates sharing one IR artifact** — a meaning-lock gate at *generation* time and a diff gate at *verification* time — of which the prior finding saw only the verification face. This both preserves the prior's real contribution AND states the demotion honestly, closing the "off-easy" gap. (Also answers user 2b: the two gates are NOT one — they are distinct temporal operations that happen to share the IR as operand.)

### CAND-3 — The IR-spine fix → **SURVIVE + REFINE**
- **Prosecution 3a (false unification):** "ONE wiring delivers BOTH gates" — the two gates are distinct temporal operations (generation-time lock; verification-time diff). Wiring the 3-Pass gives the *structure* for both, but the Pass-3 diff is still additional work that must be authored; "one wiring, both gates for free" mildly overclaims.
- **Prosecution 3c (rubber-stamp one level up — the killer objection):** will emitting a meaning-lock IR force meaning/harmony separation, or will the same fluency-biased model write the IR fluency-biased too — embedding "allegorical", "work" for *iş*, the dropped clause *into the IR* — so Pass-3 faithfully reconstructs a wrong IR? The IR forces IR↔output *consistency*, not *correctness*.
- **Defense (3c):** the IR is config-BLIND and "accurate but choppy" — its job is literal semantic completeness, not fluency. A config-blind literal rendering of *"basit avamın fehmine gelecek"* is a **different artifact type** from a polished sentence; the specific 7 errors (silent clause-drop, fluency-word capture, register-lift) are structurally *harder* in a literal-gloss mode than in a flowing-English mode. The IR **relocates generation** to a mode where those errors are harder — it does not eliminate mis-comprehension.
- **Collision → SURVIVE + REFINE**, three carried caveats: **(i)** "one wiring delivers both gates" → **"one architecture HOSTS two distinct gates; the Pass-3 diff is still distinct work."** **(ii)** the REAL-artifact + full-restructure is a *boundary* choice, justified only pending evidence the lighter (simulated) variant fails — already correctly DEFERRED. **(iii)** state honestly that the IR **relocates** generation to an error-resistant mode; it does **not** "force separation" (overclaim) and does not eliminate mis-comprehension. **Key emergent point:** the rubber-stamp objection does not kill the fix — it **vindicates the two-gate design.** Because the meaning-lock gate is *necessary but not sufficient* (mis-comprehension survives it), the post-draft diff gate is **load-bearing, not redundant.** The objection that looked fatal is the strongest argument for why *both* gates are required.

### CAND-4 — Pass-1 config-blind → **REFINE (couple it to real-vs-simulated)**
- **Prosecution (user 1d):** config-blindness is a fiction like passes-in-one-context. A model given A1–A8 in-context cannot genuinely "not condition" on them; "ignore the config for Pass 1" is as ignorable as "run three passes."
- **Defense:** there is a real structural difference. "Run three passes" asks for *temporal* separation inside one forward generation (hard — generation is one motion). But config-blindness can be enforced by *context* separation: run Pass-1 in a context where the config **literally is not present** (separate call / window) — which is exactly what the *real intermediate artifact* variant provides. Artifact-type separation (literal gloss vs polished translation) is something models do reliably.
- **Collision → REFINE:** config-blind Pass-1 is implementable **but only robustly in the real (separate-context) variant.** In the one-context *simulated* variant it degrades to "as ignorable as any instruction" — i.e., the prosecution is *correct for the simulated variant.* Finding: **config-blindness is COUPLED to the real-vs-simulated axis, not independent of it** — it is a second, independent reason to prefer real over simulated (the first being the rubber-stamp resistance at CAND-3). Mild demotion of the DEFERRED simulated variant: it doesn't just risk collapse, it also cannot deliver genuine config-blindness.

### CAND-5 — descriptive→imperative REPAIR of `harmony_layer.md` → **SURVIVE (load-bearing, not nitpicking) — shape conditional**
- **Prosecution (user 1e):** cosmetic. If Step 5 says "run Pass 1 → 2 → 3," the imperative mood lives at the invocation; the prose can stay descriptive.
- **Defense (external-anchor):** line 7 literally reads *"The idea is to create a translation mode…"* — rationale prose. A thin invocation ("run the 3-Pass") that points at rationale resolves to *rationale*, and the model narrates rather than executes — the exact observed collapse. The imperative rewrite is what makes the pointer resolve to steps.
- **Collision → SURVIVE**, one refinement: load-bearing **conditionally on where the imperative lives.** If the invocation is thin, the `harmony_layer.md` rewrite is genuine **REPAIR** (semantic). If Step 5 itself spells out the imperative gated steps, the `harmony_layer.md` edit reduces to **REORGANIZE** (separate method/policy) and the imperative-rewrite burden moves to Step 5. Either way *something* must carry the imperative mood; it is not cosmetic. (Corrects innovation's unconditional "REPAIR" label.)

### NEW FINDING — Granularity error in the IR spec (D6, externally grounded) → **REFINE innovation**
- Innovation specified the meaning-lock IR at **"word/clause granularity."** The canonical text says otherwise: Pass-1 is *"Translate every **sentence**"* (line 9) and the hard constraints **forbid** splitting a sentence into two (line 17, "sentence boundaries are structural meaning"). A word/clause-chopped IR would violate `harmony_layer.md`'s own hard constraint and risk exactly the sentence-boundary destruction the SKILL forbids.
- **Diagnosis of the slip:** innovation imported "word/clause granularity" from the **prior inquiry's *check* granularity** (diffing omissions at word/clause level is correct) and mis-applied it to the **IR's own form.** These are two different objects.
- **REFINE:** the **IR is sentence-granular** (accurate-but-choppy = every sentence rendered literally, no inter-sentence harmony yet); the **word/clause granularity belongs to the CHECK** that runs *against* the IR, not to the IR's form. Pass-3 then harmonizes *supra-sententially* using "the target language's natural cohesion devices" (line 13) without merging/splitting. This sharpens the granularity caveat and grounds the prior inquiry's "don't force sentence-chopping" constraint in `harmony_layer.md`'s literal hard constraints.

### Diagnosis 2c — is "designed subordinate" exculpatory? (D3, P2) → **SURVIVE, with a mandated both-halves framing**
- **Prosecution:** the design *declares* subordination (Tier-1 "meaning IS carried by this harmony"; Pass-3 "HOW not WHAT") but the *executed behavior* gave harmony/fluency the wheel. Using "harmony is designed subordinate" to *exclude* the user's "harmony without semantic priority" locus risks letting the design intent exculpate the execution failure.
- **Defense:** "designed subordinate" is a claim about *design intent*, and it is **true + externally confirmed** (lines 13, 33). Excluding the user's locus on that basis is correct *as far as the locus-description goes* — harmony did not *by design* override semantics.
- **Collision → SURVIVE with a required framing:** the diagnosis must state **both halves** — **designed subordinate (intent, true) + executed co-equal (the un-proceduralized passes let fluency capture word-choices).** Stated as only the first half, it is exculpatory; stated as both, it is honest and it is the same shape as inquiry 1's co-equal blame (application-failure + tool-deficiency): here **SKILL-deficiency (no proceduralization of its own method) + execution-collapse (the passes ran as one motion).** Neither the SKILL author nor the AI is let off. This must be explicit in the finding.
