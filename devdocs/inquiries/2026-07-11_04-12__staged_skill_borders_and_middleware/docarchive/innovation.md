## Phase 2 — Generate (4 Generators + 3 Framers)

### G1 · Combination *(Generator)*
- **Generic:** combine staging + the middleware files under "make the SKILL explicit" — but the surprising combination is staging + **middleware-as-forcing-function**: what if each stage must EMIT its middleware file, so the emission *makes the stage happen* (the file is a forcing function, not just visibility)?
- **Focused:** combine the staged Step 5 with prior `2026-07-11_00-24`'s "real separate step" → the minimal forcing function = require the **meaning-lock stage to emit a real IR artifact** before the harmony stage runs. The border stops being a header and becomes an artifact dependency.
- **Contrarian:** combine staging with the MISFIT → since staging doesn't fix reliability but the **mechanical config-independent checks** do, the staging's genuine payoff is giving those *verifiable* checks a defined **check-stage home** (run last, against the finished draft). Staging's value is placement-of-the-reliable-part, not the soft borders.

### G2 · Absence Recognition *(Generator)* — both levels
- **Patch-level:** the flat Step 5 lacks an explicit ORDER + stage labels + a place for the config-independent spine to run. (The staging fills this.)
- **Redesign-level (from scratch):** a from-scratch SKILL would have a **required intermediate artifact** between comprehension and generation (the meaning-lock IR — the forcing function) AND a **decision-record/changelog** for its own evolution.
- **Redesign, bidirectional (already-present-in-different-form):** the **harmony report** already is a latent runtime record; the **config/core file split** already is a latent layering. So "middleware files" and "separation" partly *articulate what's latent*; the genuinely-ABSENT artifact is the **authoring-changelog** (no per-edit SKILL record exists) — which is why it's the highest-novelty earner.

### G3 · Domain Transfer *(Generator)* — native + different
- **Native (software):** **CI pipeline stages + artifacts** — build → test → deploy, where each stage *emits an artifact the next consumes*; the artifact is both the interface AND the forcing function (deploy can't run without the build artifact). Applied: a staged Step 5 where meaning-lock emits an IR that harmony-generate consumes = the enforcement staging wants. Also **ADRs (Architecture Decision Records)** = exactly the authoring-changelog (dated "what decision changed and why").
- **Different (manufacturing):** an assembly line's WIP piece physically passes station to station — a station *can't* be skipped because the piece must pass through. In one model pass there is no physical forcing UNLESS the artifact (the IR) is made the "piece."
- **Contrarian (legal/versioning):** redline / track-changes logs = the changelog; "a middleware md per change" is a redline log — cheap, standard, exactly the authoring-changelog.

### G4 · Extrapolation *(Generator)*
- **Generic:** as the SKILL grows (more principles/policies), a flat Step-5 bag becomes unmaintainable; staged sections + a changelog scale, the flat bag does not. Argues FOR staging+changelog as maintainability.
- **Focused:** runtime-provenance cost compounds with every added rule (per-translation); the authoring-changelog cost is one-time-per-edit. Confirms the changelog scales, provenance does not.
- **Contrarian:** extrapolate the forcing-function — if every stage must emit an artifact, translation becomes multi-artifact (IR + harmony map + final): heavier per run but auditable, converging with prior `2026-07-11_00-24`'s deferred simulated-intermediate. Frontier, not now.

### F1 · Lens Shifting *(Framer)*
- **Generic:** view staging under "maintainability" vs "correctness" lenses — under maintainability it is clearly good (ordered, sectioned, extensible); under correctness it is only a probability-raiser. Honest framing: staging is **primarily a maintainability win**, secondarily a modest correctness nudge.
- **Focused:** view "middleware files" under "forcing-function" vs "visibility" lenses — as visibility (settled) the changelog earns its keep; as a forcing function (reframe) the emitted-artifact-per-stage makes staging real. Two values from one word.
- **Contrarian (the mandated reframe):** shift the lens from **prose borders → artifacts.** The seed assumes staging = prose reorganization. Under the artifact lens, the useful move is REQUIRING AN EMITTED ARTIFACT at each stage boundary — which *enforces* what a prose header only *suggests*. (Adjudicated at F3.)

### F2 · Constraint Manipulation *(Framer)* — both directions
- **ADD:** add "no new runtime artifacts / no extra token budget" → forces the CHEAPEST staging (prose headers + the authoring-changelog only; no IR, no provenance). The minimal adopt.
- **REMOVE:** remove "still one run" → allowing a real separate step/context makes the meaning-lock stage genuinely ENFORCED (Pass-1 in its own pass). But the user EXCLUDED this ("still one run") — which is *precisely why* one-run borders stay soft. The REMOVE surfaces the load-bearing tension: **the enforcement the user wants requires relaxing the one-run constraint the user imposed.**

### F3 · Inversion *(Framer)* — piece-level (i, ii) + Intervention-Shape-Axis (v), depth-checked

**(a) Content/framing-axis inversion — the mandated reframe.**
- *Assumption reversed:* "staging is a PROSE/STRUCTURE reorganization (explicit borders in the SKILL text)."
- *Level-1 (component):* "use emitted artifacts instead of prose headers."
- *Level-2 (system):* enforcing a stage boundary *in one pass* requires a **required artifact** at the boundary (the model must WRITE the meaning-lock IR before proceeding) — a header is a suggestion, an artifact requirement is a forcing function. So the user's **two ideas reunify**: the "middleware files" are not only visibility — they can BE the stage-forcing artifacts.
- *Multi-axis existence check:* could the count of NEW forcing artifacts be ONE (not per-rule)? Yes — the minimal forcing function is a **single meaning-lock IR** (prior `2026-07-11_00-24`'s "real separate step"), not a per-rule provenance trace. So the enforced-staging reframe collapses to "require ONE intermediate artifact," which IS the prior fix's deferred simulated-intermediate — reinforcing that staging ≈ the prior fix.
- *Honest resolution:* within "one run," **even an emitted artifact is soft** — the same fluency-biased model can narrate the IR fluently too (the rubber-stamp one level up — exactly prior Inquiry-2's critique of the IR). So the artifact-forcing-function only *truly* enforces if "one run" is relaxed (out of the user's stated scope). Within the constraint, an emitted IR is a **stronger probability-raiser** than a prose header (writing an IR commits more than reading a header) — but still not a guarantee. **The reframe survives as a real design axis (prose-header < emitted-artifact < separate-pass), resolving into a probability-raising GRADIENT, not a binary.**

**(b) Intervention-Shape-Axis inversion — MANDATORY (property v).**

- *What follows:* the honest committed shape for staging is **REORGANIZE + small ADD** (the cheap prose staging); the IR-artifact (Z) is the *enforced* version, **deferred/gated on relaxing one-run**. Tested both.
- *Changelog committed shape = **ADD-CONTENT*** (a new dev-side convention doc); alternative REORGANIZE (fold into existing docs) rejected — it is genuinely new. ADD-CONTENT stands.
